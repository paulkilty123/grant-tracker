Dashboard — surfacing projects & applications

/dashboard

The dashboard predates the project→application workflow: it currently shows matches, top matches, pipeline and deadlines, but represents applications only as a number in the greeting and projects not at all. This adds a "Your work" band so the home screen opens on what the user is actually doing. For the Next.js + Tailwind codebase; styling matches the live dashboard (large rounded cards, green text-link actions, coral accents).

What changes

  • Add a "Your work" band as the first two-column row, directly under the greeting and above "Worth your attention". Existing panels (matches, top matches, pipeline, deadlines) are unchanged and shift down.
  • Continue writing card — the user's in-progress applications with writing progress (n of m · %) and nearest deadline (overdue/soon flagged coral). Rows are click-through to the editor; header has a "View all N →" link. No filled buttons (matches the live panel style).
  • Your projects card — each project's match-readiness and "N funders fit", with a "View all →" link and a "+ New project" green text link.
  • Reword the greeting summary to lead with the work: e.g. "2 projects ready to match · 7 applications in progress · 2 deadlines this week".
  • Empty state (no projects and no applications): the band collapses to a single "Start your first project" card — see mockup. Steers to the project route as primary, with a direct-application secondary link.

Reading order

Top → bottom: your work (resume) → matches (discover) → pipeline & deadlines (track). For a returning user, resuming in-flight work beats scanning new matches, so the band earns the top slot.

States

Populated: two cards (mockup A). All-empty: single card (mockup B). Partial — projects but no applications: left card shows projects; right card reads "No applications yet — pick a funder from a project to start". Partial — applications but no projects: left card shows applications; right card prompts "Describe a project to match more funders".

Style tokens (match live dashboard)

Cards: white, 1px #ece7da border, radius 22px, padding ~26px. Card heading: Space Grotesk 21px/600. Actions: green text links #4e8636 with " →" (no filled buttons in panels). Progress bar: #7cb342 on #efe9dd. Deadline/overdue pill: text #c0492a on #f8e3da. Monograms: applications use pale-green #eaf3de/#3b6d11; projects use #f3ece0/#c47f1a. Empty-state primary button: #5f9c34 filled (an empty/onboarding exception to the no-button rule).

Open decision — Pipeline vs "Continue writing"

The existing Pipeline panel (Identified / Applying / Submitted / Won, by £ value) and the new "Continue writing" card both touch applications, with overlapping language ("Applying" stage vs "in progress" applications). They are different things: Pipeline = where each opportunity sits and its value; Continue writing = the actual answer-writing in flight.

Recommendation: keep both but relate them — e.g. a one-line caption on Pipeline ("tracking value by stage") and on Continue writing ("answers you're drafting"), and make the Pipeline "Applying" tile link through to the relevant applications. Decide this before wiring up the band so they aren't built as two unrelated things. Do not merge them yet.
