Application answer editor — redesign

/dashboard/applications/[id] · per question

A draft-first flow for writing a single application answer, in three states: empty → drafted → checked. The problem today is that the empty textarea is the visual centre while "draft a starting version" is a small link beneath it — so it's unclear where to start. For the Next.js + Tailwind codebase; no app code changed.

What changes

  • Lead with the draft action. When an answer is empty, replace the empty textarea with a "Start with a draft" panel: primary "Draft a starting version" button, the 3-step path (Draft → Review & check → Make it yours), and "write it from scratch" as a quiet secondary link. Icon is ti-file-pencil (document + pencil) — not sparkles/wand.
  • Score/tips panel is inert until there is content — no premature "Check this answer" on an empty answer; it reads "appears once you've drafted or written".
  • After drafting: the draft fills the editor with a "Draft — review and make it yours" badge; primary action becomes "Check this answer"; "Redraft" sits alongside; editing happens directly in the box.
  • After checking: score chip and ring are tier-coloured (4.5/10 = amber chip, coral ring — not green), with a one-line reason ("capped by an unresolved placeholder").
  • Link flags to the text. "Jump to next fix (n of m)" steps through gaps; placeholders render inline in the answer as a highlighted gold block ("needs your input"), instead of raw **markdown** at the bottom.
  • Sentence case throughout (your answer, tips to improve, next best fix, guide). A step indicator shows where the user is in the flow.

Tokens used on this screen

Primary action: forest #1f5c52 filled, one per state. Headings/UI: Space Grotesk. Body: Plus Jakarta Sans. Status badges (one system):

within limit / done needs attention blocking gap neutral / not started

Score tiers: ~7+ green, ~4–6 amber, <4 coral/red. The ring colour matches the chip.
