# Handoff: two reading jobs for a Sonnet 5 session

Written 2026-09-07 by the orchestrating session (grant-tracker-be). Read
`CLAUDE.md` first, all of it. Then the timing, amounts and verdicts briefs in
this folder and their results files: every rule and every trap in them
applies here, word for word. Then this. Message grant-tracker-be after every
push with the batch's counts and anything that needs a decision.

Both jobs are reads whose result the checker can confirm against the page.
Nothing here decides anything: a wrong write is reverted, a doubtful one is
reported. No Anthropic API spend at all: read pages with node's fetch and a
browser user agent, never curl; no `@anthropic-ai/sdk`, no
`/api/admin/enrich-grant`. Zero model calls is the budget.

## Job 1: how the money may be spent, on 116 live grants

Paul, 7 Sept: the card's type label should read Grant plus Restricted,
Unrestricted or Capital. 190 rows were filled today from spending facts the
row already held. These 116 live grants hold nothing: the row list is
`docs/handoffs/spend-rows-2026-09-07.json`. Batches of 20, in file order.

For each, read the funder's page (and one linked guidelines page if the
apply page is silent, citing the page you read) and write, with the page's
sentence as citation, `source_url` on every citation, source
`user_verified:spend-2026-09-07`:

| the page says | write |
|---|---|
| unrestricted, core costs, running costs, "can be spent on anything", general funding | `spend_restriction: 'unrestricted'`, `funding_subtypes: ['unrestricted']` |
| project costs only, "we do not fund core costs", restricted to the project applied for | `spend_restriction: 'restricted'`, `funding_subtypes: ['restricted']` |
| capital, buildings, equipment, refurbishment, vehicles | add `'capital'` to `spend_types` and to `funding_subtypes` (alongside restricted or unrestricted where stated) |
| revenue, salaries, activities, running a service | add `'revenue'` to `spend_types` |
| the page states nothing about what the money may be spent on | nothing; report `not_stated` with the closest sentence |

`funding_subtypes` values for a grant are only `unrestricted`, `restricted`,
`capital`, `emergency`, `small_grant` (see `src/lib/funding-subtypes.ts`).
Never infer restricted from silence: a page that names a project theme
without saying core costs are excluded has not said restricted. A quote
must be about THIS fund, not a sibling on the same page. Admin-held fields
(the JSON says which) are reported, not overwritten.

Count SQL after each batch, restricted to the 116, by name as the timing
job's count script does:

```sql
select count(*) from scraped_grants
where is_active and pipeline_state='published' and funding_type='grant'
  and (funding_subtypes is null or funding_subtypes = '{}');
```

Results: `docs/handoffs/spend-results-2026-09-07.json`, a dict with
`batches` and a closing `summary`, written and reported per row as the
amounts job did.
