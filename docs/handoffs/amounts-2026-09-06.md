# Handoff: amounts on 176 live rows

Written 2026-09-06 by the orchestrating session for an Opus 5 session to run.
Read `CLAUDE.md` first, all of it. Then `docs/handoffs/timing-2026-09-06.md`
and its results file, because this job has the same shape and inherits every
rule and every trap found there. Then this.

## The job in one sentence

176 live rows show a fundraiser no amount at all: `amount_min` and
`amount_max` both null. Read each funder page and record the figure a single
applicant can ask for, with the page's own sentence as the citation. Where the
page states no per-applicant figure, write nothing and say so.

The row list is `docs/handoffs/amount-rows-2026-09-06.json` (123 grants, 9
programmes, 34 in-kind, 10 investment). Work it top to bottom in batches of
20. Do not touch any row not in the list.

## What a fundraiser must be able to tell from the row

"A fundraiser landing here knows roughly how much they could ask for." The
figure that answers it is the **per-applicant award**. Nothing else is.

| the page says | write |
|---|---|
| "grants of up to £10,000" | `amount_max: 10000` |
| "grants of between £1,000 and £5,000" | `amount_min: 1000, amount_max: 5000` |
| "grants from £500" with no ceiling | `amount_min: 500` only |
| "average grant £3,000", "typically around £2,500" | nothing in the columns; put it in `funder_brief.typical_award` with the quote |
| "we award £2 million a year", "a £15 million fund", "£4m to £6m annually" | **nothing**. That is the pot, not the award. Put it in `typical_award` as "the fund's total, not a per-grant figure" |
| a figure per unit ("£2.15 per tree", "£100 per young person") | nothing in the columns; `typical_award` carries the rate |
| several strands with different ceilings on one page | the ceiling of the strand this row is about; if the row is the whole programme, the highest ceiling and `typical_award` names each strand |
| a loan or investment: "loans of £50,000 to £500,000" | `amount_min`/`amount_max` as for grants; the row's `funding_type` already says it is not a grant |
| a listing site (Funding for All, Idox, GRANTfinder, a council's "funding finder") states a ceiling the funder's own page does not | **nothing**. Backstage Trust carried "up to £500,000" from Funding for All for three months; the trust states no maximum. A listing site's figure is evidence only when the funder's own site has no page for the fund at all, and then at `confidence: 'low'` with the listing named in the citation |

**Two figures that look like awards and are not:** an organisation's income
cap ("for charities with income under £500,000" goes in `max_org_income`, not
here), and match-funding or a percentage of project cost ("we fund up to 50%").
Neither is written to the amount columns.

## Rules that are not optional

1. **Every write carries a quote that appears on the page**, with the number
   in it, copied as the page prints it. The checker confirms quotes against the
   page; a paraphrase or a number the page does not print fails it, and the row
   is reverted.
2. **Read the page, not the brief.** `brief_typical_award` in the JSON is a
   model's summary from months ago. It is where the wrong figures came from.
   50 rows have a `£` in their description; treat those as a hint to look, not
   as evidence.
3. **Read with node's fetch and a browser user agent**, never curl (brotli),
   and treat a 200 with an empty body, or headings with nothing under them, as
   unread, never as "states nothing". A 403 or a JS-only page goes to `report`
   as `unreadable`. Zero model spend: no `@anthropic-ai/sdk`, no
   `/api/admin/enrich-grant`.
4. **The apply_url may not be the fund's page.** Follow the link to the fund's
   own page, cite that URL in `source_url`, and bank it in `grant_sources`. Do
   not change `apply_url` in this job; if the link is wrong, say so in
   `report` as `wrong_link` with the right URL.
5. **A quote must be about this fund.** The timing job's three near misses
   (Islington Giving, Kusuma, Open Society) were all true sentences about a
   different fund on the same site. A ceiling for a sibling fund is not this
   row's ceiling.
6. **Source is `user_verified:amounts-2026-09-06`.** Never `admin:`. Eleven
   rows in the list hold their null under an admin source; if the merger
   refuses, log `pinned` with the quote and move on. Match on who blocked the
   write, not on the reason string (an admin source without `pinned: true`
   refuses as `lower_trust`).
7. **Write the columns and `typical_award` in separate calls**, columns first,
   and only update `typical_award` when the column write was applied or the
   figure belongs in prose only. Same derivative rule as the timing job.
8. **Dry run first, every batch.** Read the printout against the quotes before
   `--apply`.
9. **Prove the count, by name.** After each batch run the count script from
   the timing job adapted to this SQL, restricted to the 176, listing any row
   that gained a figure outside the results file with its provenance:

```sql
select count(*) from scraped_grants
where is_active and pipeline_state='published'
  and amount_min is null and amount_max is null;
```

10. **Commit after every batch**, script and results file together, and push
    to `main`. `npx tsc --noEmit` before every push, no exceptions. Message
    grant-tracker-be after each push with the commit, counts and anything
    that needs a decision.

## The script shape

One script per batch, `scripts/amounts-batch-NN-2026-09-06.ts`, in the shape
of the timing batch scripts: a `ROWS` array, a title check that throws on a
wrong row, dry run by default, `--apply` to write, `mergeGrantUpdate` for
every write, citations keyed on the column (`amount_max`, `amount_min`), one
quote per column, `source_url` on every citation.

## Results file

`docs/handoffs/amount-results-2026-09-06.json`, a dict with `batches` and a
closing `summary`, appended per batch:

```json
{ "batch": 1,
  "written": [{ "id": "…", "min": null, "max": 10000, "prose_only": false }],
  "report": [{ "id": "…", "why": "not_stated|pot_only|per_unit|listing_only|unreadable|wrong_link|index_over_programmes|pinned|invite_only", "quote": "…", "url": "…" }] }
```

`not_stated` needs the closest sentence the page has about money, so the
reviewer can see it was looked for. `pot_only` needs the pot sentence.

## What the orchestrating session checks afterwards

The checker re-reads every written row's page and confirms or contradicts
each figure against the text; a contradicted figure is reverted. The count is
re-derived by name. A wrong figure a fundraiser sizes an ask against is worse
than none, so when unsure, report rather than write.
