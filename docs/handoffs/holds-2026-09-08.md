## The job in one sentence

Fifteen rows, three small jobs, all of them reading rather than deciding:
six review rows whose page could not be read from a script on 7 Sept, seven
review rows whose `apply_url` is a home page or an index and needs pointing
at the fund's own page, and three live rows with no amount where the page
deserves one careful read. Nothing changes state. Nothing goes live: the
launch freeze means every publish is Paul's click, each time.

Do the three jobs in order, one commit each. Every row is listed below with
its id; touch no other row.

## Standing rules (from the verdicts brief, repeated because they matter)

1. **Nothing changes state.** No `is_active`, no `pipeline_state`, no
   `rejection_reason`, no `needs_intervention_reason`. A reject or a publish
   exists only in the results file until Paul acts.
2. **Every write carries the page's own sentence** with the date or number in
   it and `source_url` on every citation. Source is
   `user_verified:holds-2026-09-08` (trust 70) for anything read off the page
   today. Never `admin:`. `system:` only for an inferred value.
3. **Admin-held fields are reported, not overwritten.** They are listed per
   row below. If the page contradicts one, the verdict is `hold` with both
   sentences.
4. **Read with node's fetch and a browser user agent, never curl.** An empty
   body, a Cloudflare interstitial, or headings with nothing under them is
   unread. Try the laptop first: on 7 Sept "unreadable" turned out to be
   per-origin, and Allen Lane read fine from here. If fetch is refused, open
   the page with the Chrome browser tools and read the rendered text. If that
   fails too, the row stays `hold` with `unreadable` and the error text.
5. **No Anthropic API spend.** No `@anthropic-ai/sdk`, no
   `/api/admin/enrich-grant`, nothing that hits `api.anthropic.com`.
6. **A `publish` verdict needs a complete seven-field brief written from the
   page**, per the verdicts brief, and a dedup query in SQL first.
7. **Never divide a pot by a grant count.** A yearly total is `pot_only`.
8. **Dry run, `npx tsc --noEmit`, commit after every job**, script and
   results file together, push to `main`. Commit message in a file,
   `git commit -F`, attribution block from CLAUDE.md. Data scripts are
   admin-only and merge on green.

## Script shape

One script per job, `scripts/holds-job-N-2026-09-08.ts`, in the shape of
`scripts/verdicts-a01-2026-09-07.ts`: a `ROWS` array with a title regex that
throws on a wrong row, dry run by default, `--apply` to write,
`mergeGrantUpdate` for every write, `getAdminDb` for the client.

## Results file

`docs/handoffs/holds-results-2026-09-08.json`, a dict with `jobs` and a
closing `summary`. Each verdict in the verdicts brief's shape:

```json
{ "id": "…", "title": "…", "job": 1, "verdict": "publish|park|reject|hold",
  "code": "<reject code, reject only>", "quote": "…", "url": "…",
  "read_via": "fetch|browser|unreadable",
  "tidied": ["apply_url", "amount_max"],
  "candidates": [{ "url": "…", "note": "…" }],
  "for_paul": "one sentence: what he is deciding and why it is his call" }
```

Job 3 entries use `written` and `report` as the amounts brief does. End with
a `paul_list`, `publish` first, then `park`, `reject`, `hold`, one line each.

## What grant-tracker-be checks afterwards

Every relinked `apply_url` opened and tested against the 17 Aug rule; every
written amount and date re-read against its page; the checker run on every
tidied row; the no-amount count re-derived; and a query proving that no row's
`is_active` or `pipeline_state` changed during the job. A wrong quote is
reverted, so when unsure, report rather than write.
