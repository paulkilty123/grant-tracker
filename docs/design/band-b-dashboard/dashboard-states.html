What day one taught me that I'd have got wrong

The deadlines card is not empty on day one. I assumed it would be. It isn't — alerts is built from pipeline rows plus catalogue rows, so a brand-new account with nothing saved still gets deadlines drawn from its own matches. That's a genuinely good behaviour and it changes the card's job: on day one it's a discovery surface, not a tracker. I've added one line under it saying where the dates come from, because otherwise a user with an empty pipeline reasonably wonders how the app knows about deadlines at all.

Matches is populated too, because matching runs off the organisation profile from onboarding. So of the six blocks, only applications, projects and pipeline are actually empty — the page is far less barren than "new user" suggests, and it doesn't need an artificial welcome hero to carry it.

The empty cards each make one offer, not three. Dashed border, muted glyph, one sentence saying what the card will hold, one button. The pipeline's empty row explains the mechanism — save a match and it appears in Identified — because an empty four-stage ladder is otherwise just four dashes.

Two details worth noticing across the three

The greeting changes on day one — "Welcome, Paul." rather than "Good evening, Paul." It's the same slot doing a different job, and it's the one place the old onboarding warmth still belongs.

Deadlines never go red on the steady page. All four rows are beyond 30 days, so they're plain with outlined pills. Put states 1 and 2 side by side and the deadline card alone tells you which week you're in — the urgency treatment is doing real work rather than decorating.
