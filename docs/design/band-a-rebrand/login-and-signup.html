Benefits copy on the signup panel is lifted from live landing sections, not invented — so marketing and signup say the same thing. Sprout mark still a stand-in. Nothing written to the codebase.

Google sign-in is not currently wired up

Your Supabase project has 31 auth identities and every one of them is email — zero Google, none ever. So a "Continue with Google" button today would be decorative. Enabling it is a config job, not a design one: a Google Cloud OAuth client plus the provider toggle in Supabase Auth, maybe an hour, and it has to land before the Code session builds the button rather than after.

I've drawn both states below so you can decide without redesigning later. My read: worth doing — your users are charity and CIC staff who mostly live in Google Workspace, and it removes a password from the launch funnel. But if it slips, ship email-only; the card below is designed so the Google block lifts out cleanly without leaving a hole.

A

Login — refined

Your pick, tightened: card up to 22px radius, fields on white against cream, tertiary "Forgot password?" sitting on the label row rather than floating, and the whole card vertically centred. Sign-in is the only primary on the page, so nothing competes with it.
