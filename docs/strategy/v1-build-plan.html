v1 build plan

The scoped spine that proves the core bet — the connected strategic companion, grounded in the existing engines. Sequenced for Claude Code, in dependency order.

Companion to the strategy brief · 2 June 2026 · timings are Code-paced, not man-hours — calibrate against your own observed velocity

The one distinction that governs the timeline

v1 work splits into two categories paced by completely different things. Buildable work (foundations, surfaces, plumbing) is where Code is genuinely fast and conventional estimates overshoot — known engineering against existing assets. Quality-iteration work (the reasoning core, the upload extraction) is NOT paced by coding speed — Code writes it fast, but elapsed time is the judgment loop of getting the reasoning consistently good across real situations. Code's speed advantage is large on the first and small on the second.

So the way to compress v1 is not to code faster (Code already is) — it's to keep scope ruthlessly tight, and to attack the reasoning quality early and directly, testing it with real cohort situations before building the full surfaces around it. Prove the uncertain part cheaply, then build around what works.

What v1 deliberately excludes

Application builder and CRM / relationship layer — pulled forward by cohort evidence toward "v1.x soon," but not v1; they belong in the fuller companion tier as they arrive. Team functions (segment 7, org tier) and multi-org (segment 6, consultant tier) — later, tier-defining. The central brain — not buildable until data accumulates; v1's only job toward it is capturing the data + consent foundations cleanly (in phase 1). Contracts as a funding type — deferred to the SEUK conversation; keep the taxonomy clean enough to add it later. Live web search in the user-facing agent — kept in the backend pipeline (cost + the unverified-data trust problem).

Buildable spine
~3–5 wks

Foundations, surfaces, onboarding wizard, email, trial, cost controls. Where Code is fast and estimates overshoot. Steady solo work; faster in concentrated bursts.

Reasoning iteration
~4–8 wks

The reasoning core + upload extraction to consistently-good. Judgment-paced, overlaps the build. The variable that sets short vs long end.

v1 elapsed (overlapping)
~6–12 wks

Focused solo work. The range is driven almost entirely by reasoning-quality iteration, not building. Calibrate against your own Code velocity.

The honest risk. "Good enough to demo" and "good enough to consistently justify a paid companion" are different bars. The MCP captures cleared the first; v1 has to clear the second, in a richer assembled-context setting. Closing that gap is the reasoning-iteration work, and it tends to take longer than expected even when the code is fast — because it's paced by getting it right, not getting it written.
The levers you control. Faster: ruthless scope discipline (resist pulling the execution layers forward); reuse the existing engines (v1 wraps, doesn't rebuild); test the reasoning early with the cohort before building surfaces. Slower: reasoning proving hard to make consistent; the upload extraction fighting you; scope creep; and the never-finished data-fidelity work the agent quality keeps depending on.
Why this sequence. Foundations first (everything depends on them) → reasoning core tested cheaply and early (front-load the uncertainty, validate the core bet before investing in surfaces) → onboarding and surfaces built around what's proven to work → proactive + trial last (they make it a companion and bridge to paid, but need the rest in place first). Feed Code scoped increments in this order rather than building broad and shallow.
